# Security policy

sidegig runs on every page with broad permissions, so security reports matter.

## Report a vulnerability

Do not open a public issue. Use GitHub's private report form:
[Report a vulnerability](https://github.com/neerajbhargav/sidegig/security/advisories/new).

Include the browser and version, the sidegig version (Settings, or `manifest.json`), the steps, and what an attacker gains.
You get a reply within 7 days. Fixes ship as a new release; the advisory credits you unless you ask otherwise.

## Supported versions

Only the latest release gets fixes.

## Scope

The boundaries sidegig defends, and where each is enforced, are in the README's [Security model](README.md#security-model).
Known trade-offs (for example, app frames run without the app's own CSP) are documented there and are not vulnerabilities by themselves.
